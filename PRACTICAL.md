# Чакалня - план

## Данни
- Нов модел WaitingRoomEntry: user (OneToOne към User) и created_at.
- OneToOne = максимум една заявка на потребител.
- Game и Player си остават същите.

## Операции
- join: ако вече чака или е в waiting/active игра -> отказ, нищо не се променя. Иначе се създава заявка.
- leave: трие заявката на потребителя. Ако няма такава -> нищо.
- form_game: взима допустимите чакащи. Ако са под 3 -> нищо. Иначе избира random 3, прави Game (waiting) и 3 Player с различни цветове и score 0, трие само техните заявки. Всичко е в transaction.atomic, за да няма половин игра при грешка.

## Кога се сформира
След всяко успешно join, в същата заявка.

## API
- POST /api/waiting-room/join/
- POST /api/waiting-room/leave/

## Тестове
- 5 чакащи -> 1 игра с 3 играча, 2 остават.
- 2 чакащи -> нищо не се променя.
